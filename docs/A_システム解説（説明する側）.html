1. 何を解決するか

商品ごとの在庫数と直近の出荷実績から、いつ・何を・いくつ発注すべきかを自動で判定します。

課題起きていたことこのシステムでの見え方
欠品気づいたときには在庫が無く、納期を落とす 欠品 欠品リスク が優先度Aで出る
発注漏れ発注したつもりが抜けていた 発注漏れ が優先度Aで出る（行ごと赤くなる）
過剰在庫置き場と資金が在庫に寝ている 過剰在庫 滞留在庫 が優先度Cで出る
在庫精度帳簿と現物が合わない 棚卸差異 が優先度Cで出る

5. 在庫はこう動く

在庫は出荷のぶんだけ毎日減り、入荷でまた増えます。このノコギリの形のどこにいるかで、発注すべきかが決まります。

図3　在庫の推移と3本の線。発注点を割った日に発注すれば、 リードタイム中に安全在庫を少し食うだけで入荷が間に合います。
線意味割ったら／超えたら
適正在庫上限持ちすぎない上限。リードタイム＋安全在庫＋発注サイクル分 超えると 過剰在庫
発注点リードタイム中に売れる分 ＋ 安全在庫 割ると 発注推奨
安全在庫納期の遅れや急な注文に備える分ここを割ると危険水域

6. 計算式

有効在庫       = (実棚在庫 があれば実棚 / 無ければ理論在庫) − 引当数
在庫ポジション  = 有効在庫 + 発注残数        ← 発注判定はこの値で行う
平均日次出庫    = 期間出庫数 ÷ 30日
在庫日数       = 有効在庫 ÷ 平均日次出庫
欠品予測日      = 今日 + 在庫日数
安全在庫       = 平均日次出庫 × 安全在庫日数(既定7日)
発注点         = 平均日次出庫 × リードタイム + 安全在庫
適正在庫上限    = 平均日次出庫 × (リードタイム + 安全在庫日数 + 発注サイクル14日)
発注推奨数      = 適正在庫上限まで戻す量を、MOQ と発注ロット単位に切り上げた数
発注期限日      = 欠品予測日 − リードタイム
なぜ「有効在庫＋発注残」で判定するのか。 手元の在庫だけで見ると、発注済みの商品にも毎日「発注してください」と出続けます。 そうなるとアラート自体が信用されなくなり、本当に危ない行も見逃されます。

商品ごとに変えられる値

項目効き方
発注リードタイム日数発注点計算の中核。長いほど早めに発注点に当たる
安全在庫日数空欄なら既定7日。切らしたくない商品は長くする
最小発注数(MOQ)発注推奨数の下限
発注ロット単位ケース入数など。発注推奨数はこの倍数に切り上がる

8. 設定できること

判定パラメータ（全商品に共通）

項目既定 大きくすると小さくすると
消化傾向の集計期間30日 判定が安定するが、需要の変化に鈍くなる季節変動に追従するが、数字がブレやすい
安全在庫日数（既定値）7日 欠品しにくくなるが、在庫が増える在庫は減るが、欠品リスクが上がる
発注サイクル14日 発注回数は減るが、1回の量と在庫が増えるこまめな発注になり、事務負荷が上がる
滞留とみなす日数90日 滞留の警告が出にくくなる季節商品が滞留扱いされやすい
棚卸差異を見逃す範囲0 小さなズレを無視できる1個のズレも棚卸差異として出る
いじる順番。まず既定のまま1か月運用し、「欠品が出た商品は安全在庫日数を延ばす」 「毎週同じ商品で発注推奨が出て事務が重いなら発注サイクルを延ばす」というように、 実績を見てから1つずつ動かすのが安全です。

図5　カテゴリごとに「接頭辞＋連番」を決めておくと、新規登録時に発番できます。

9. データの入れ方

図6　旧スプレッドシートからの移行。書き出してそのまま取り込むだけです。

自動計算列（有効在庫・発注点・アラート区分など）が入っていても読み飛ばすので、シートをそのまま出して構いません。 必須は「商品コード」と「商品名」の2つだけで、並び順は問いません。

毎日のデータは部分更新で入れられる

図7　CSVに載っていない列は現在値のまま。だから毎日の販売データを部分更新で流せます。

入出庫を入れると判定の材料が変わる

図8　出庫を1件でも登録した商品は、期間出庫数を台帳から自動集計します。 商品ごとに切り替わるので、全商品を一度に揃える必要はありません。

10. 運用上の注意

判定は保存していない

有効在庫・発注点・アラート区分などはデータベースに持たず、画面を開くたびに計算しています。 だから「再計算を忘れて古い判定が残る」ことがなく、数字を直せばその場で判定が変わります。 裏を返すと、これらの列は直接編集できません。もとになる数字を直してください。

アラートは機械、対応は人

対応状況（発注済み・保留・廃盤・発注NG）の列は、計算で書き換わることが絶対にありません。 「発注漏れ」と出ていても、対応状況が「発注済み」なら手当て済みとして扱います。

日次アラート

優先度A・Bの一覧を毎朝メールで送れます（設定したときのみ）。 画面を開かなくても気づけるので、朝いちばんの確認をメールに寄せる運用もできます。

導入の進め方。 ①旧シートをCSVで取り込む → ②マスタ（仕入先・保管場所・出荷先）を自社のものに直す → ③1〜2週間そのまま運用してアラートの出方を見る → ④多すぎる／少なすぎる区分があれば 判定パラメータか商品ごとのリードタイム・安全在庫日数を調整、の順が安全です。
