CSV取込と移行

スプレッドシートからの引っ越しと、毎日のデータ取込。

欠品 / 発注漏れ / 過剰在庫 / 在庫精度（棚卸差異）を、在庫数と出荷実績から自動で判定するシステム

1. 旧スプレッドシートから移す

図10　移行の流れ。旧シートを書き出して、そのまま取り込むだけです。
  1. 旧シートを開き、ファイル → ダウンロード → カンマ区切り形式(.csv)
  2. 「取込・書き出し」の商品CSVで、そのファイルを選ぶ
  3. 「内容を確認する」を押す。新規・更新・エラー・要確認の件数と、先頭20件が表示される
  4. 問題なければ「◯件を取り込む」
表示意味
新規に追加その商品コードがまだ無い行
既存を更新商品コードが一致した行。CSVに載っている列だけ上書きする
取り込めない行商品コードが空、数値や日付が読めない、コードが重複、など。その行だけ飛ばして続行
確認が必要マスタに無いカテゴリ・単位・保管場所・仕入先。取り込んだうえで知らせる
マスタに無い値でも取込は止まりません。 止めてしまうと移行が進まないためです。取り込んだあとに「確認が必要」の一覧を見て、 マスタに足すか、商品側の表記を直してください（対応状況だけは選択肢からしか選べません）。

2. 毎日のデータ取込（部分更新）

CSVに載っていない列は、いまの値のまま残ります。 だから、販売データから出した「商品コード＋期間出庫数」だけのファイルを毎日流し込めます。

図11　部分更新の効き方。単価やリードタイムが0に戻ることはありません。

商品CSVで取り込める見出し

必須は「商品コード」と「商品名」の2つだけ。並び順は問いません。

区分見出し
対応状況対応状況
基本情報商品コード / 商品名 / カテゴリ / 規格・型番 / 単位 / 保管場所
仕入先・発注条件仕入先コード / 仕入先名 / 仕入単価 / 販売単価 / 発注リードタイム日数 / 最小発注数(MOQ) / 発注ロット単位
在庫状況理論在庫数 / 実棚在庫数 / 引当数(受注残) / 発注残数(入荷予定) / 入荷予定日
消化傾向・発注判定期間出庫数(直近30日) / 安全在庫日数
履歴・管理最終入庫日 / 最終出庫日 / 最終棚卸日 / 備考

これ以外の見出し（有効在庫数・発注点・アラート区分など、システムが計算する項目）は読み飛ばします。

3. 入出庫CSV

販売管理・受発注システムから出した明細を、そのまま台帳に流し込めます。

見出し必須書き方
日付必須2026/09/25 / 2026-09-25 など
区分必須入庫 / 出庫 / 調整（入荷・出荷・払出などの言い換えも読む）
商品コード必須登録済みの商品コード
数量必須入庫・出庫は正の数。減らす調整はマイナス
出荷先—出庫の行だけ。出荷先マスタの名前
入庫元—入庫の行だけ。自由入力
伝票番号 / 備考 / 商品名—商品名は照合に使わない（人が読むための列）
入出庫CSVは、1行でも読めない行があると1件も取り込みません。 在庫を動かす台帳なので、半分だけ入った状態になると理論在庫が合わなくなり、 後から原因を追えなくなるためです。エラーを直してから、もう一度確認してください。

マスタに無い出荷先があるとエラーになりますが、「マスタに無い出荷先を自動で追加する」に チェックを入れると、名前だけの出荷先を作って取り込みます（住所などは後から「出荷先」画面で補えます）。
